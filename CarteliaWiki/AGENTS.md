# AGENTS.md — CarteliaWiki

## 1. Общая информация о проекте

CarteliaWiki — локальный сайт-вики для вымышленного мира Cartelia.

Цель сайта — удобно хранить и просматривать лор мира: устройство Церкви, богов, расы, народы, фракции, магию, географию, миры и другие элементы сеттинга.

Это НЕ сайт о персонажах. Отдельный раздел «Персонажи» создавать не нужно, если пользователь прямо не попросит об этом.

Проект создаётся постепенно. Архитектура должна позволять добавлять большие объёмы лора без необходимости переписывать основной JavaScript и HTML.

---

# 2. Главный принцип работы

Разделяй:

1. Данные мира.
2. Логику сайта.
3. HTML-структуру.
4. Стили.

Не помещай большое количество информации о мире непосредственно в `index.html` или `script.js`.

По возможности:

- данные мира хранятся в `data/*.js`;
- `script.js` отвечает за общую логику и отображение;
- `style.css` отвечает за внешний вид;
- `index.html` содержит структуру сайта и основные контейнеры.

Если пользователь добавляет новую информацию о мире, сначала подумай, в какой файл данных она должна попасть.

# 4. Девять основных систем мира

В проекте сейчас предусмотрены следующие основные системы:

1. Церковь — `church.js`
2. Ордена — `orders.js`
3. Расы — `races.js`
4. Народы — `peoples.js`
5. Фракции — `factions.js`
6. Боги / божественная иерархия — `gods.js`
7. География — `geography.js`
8. Магия — `magic.js`
9. Миры — `worlds.js`

Не смешивай эти системы без причины.

---

# 5. Важное различие между системами

В мире Cartelia:

- раса;
- принадлежность;
- разумность;
- народ;
- фракция

не являются одним и тем же.

Не объединяй их в одну систему только ради упрощения кода.

Например:

Человек → раса.

Разумный → категория разумности.

Ибель → принадлежность.

Конкретный человеческий народ → народ.

Государство или политическое образование → фракция.

# 6. Церковь

Церковь является одной из самых сложных систем сайта.

Навигация должна иметь иерархию:

Церковь
→ Ветвь
→ Палата
→ Тема
→ Статья

Пользователь должен иметь возможность:

1. открыть раздел «Церковь»;
2. выбрать ветвь;
3. выбрать палату;
4. выбрать тему;
5. открыть соответствующую статью.

---

# 7. Ветви Церкви

Существуют три основные ветви:

- Серебряная ветвь — Китиль
- Золотая ветвь — Ибель
- Лазурная ветвь — Алимеса

Не добавляй новые ветви без указания пользователя.

# 8. Серебряная ветвь

Известные палаты Серебряной ветви:

- Палаты Упокоения
- Палата Доблести
- Палата Истины

Палата Доблести включает, среди прочего:

- Святые ордена
- Регулярную армию

Палата Истины включает, среди прочего:

- Судебную систему
- Законодательство
- Инквизицию

Орда́на являются частью Церкви.

Технически данные орденов могут находиться в отдельном `orders.js`, но в интерфейсе ордена должны восприниматься как часть структуры Церкви.

# 11. Расы

Основной раздел:

Расы

Внутри него используется отдельное понятие:

Принадлежность

Принадлежность не является просто названием расы.

Известные принадлежности:

## Ибель

Категории:

- Разумные
- Полуразумные
- Неразумные

## Китиль

Категории:

- Гниющие
- Кровососущие
- Сотканные из тьмы

## Пепел

Пепельные существа относятся к отдельной принадлежности.

«Сотканные из тьмы»

на:

«Тёмные»

если пользователь специально не попросит об этом.

# 12. Расы и народы

Расы и народы — разные системы.

`races.js` отвечает за расы.

`peoples.js` отвечает за народы.

Например:

Человек — раса.

Конкретный человеческий народ — народ.

Человеческие народы могут быть разделены на:

- многочисленные;
- малочисленные.

Не смешивай классификацию народов с классификацией рас.

---

# 13. Магия

Магия является самостоятельной системой.

Файл:

`data/magic.js`

Каждая раса может иметь собственную магию.

Не помещай всю информацию о магии непосредственно в `races.js`.

Раса может ссылаться на соответствующую магическую систему.

Например:

{
    name: "Фелленим",
    magic: "fellenim"
}

А подробности находятся в:

`magic.js`

Это позволяет изменять описание магии независимо от описания расы.

# 18. HTML

`index.html` должен содержать преимущественно:

- каркас страницы;
- боковую навигацию;
- контейнеры разделов;
- подключение CSS;
- подключение файлов данных;
- подключение `script.js`.

Не превращай `index.html` в огромный файл с полным лором мира.

Например, для Церкви предпочтительно:

<section id="church">
    <div id="church-content"></div>
</section>

А содержимое генерируется JavaScript.

---

# 19. JavaScript

`script.js` отвечает за:

- навигацию;
- переключение разделов;
- открытие статей;
- генерацию интерфейса;
- работу с данными из `data/*.js`.

Не создавай огромные конструкции вида:

if (race === "fellenim") {
    ...
} else if (race === "darbol") {
    ...
} else if (...) {
    ...
}

если проблему можно решить универсальным отображением данных.

Предпочтительно создавать универсальные функции.

Например:

showChurch()
showChurchBranch()
showChurchChamber()
openChurchTopic()

и аналогичные универсальные функции для других систем.

---

# 20. Данные должны быть отделены от логики

Плохо:

function showRace() {
    document.innerHTML = `
        <h1>Фелленим</h1>
        <p>Огромный текст...</p>
    `;
}

Хорошо:

const races = {
    fellenim: {
        name: "Фелленим",
        description: "...",
        magic: "fellenim"
    }
};

А JavaScript только отображает эти данные.

---

# 21. Подключение файлов

Если `script.js` использует переменную из другого JS-файла, файл с данными должен быть подключён раньше.

Например:

<script src="data/gods.js"></script>
<script src="data/church.js"></script>
<script src="data/orders.js"></script>
<script src="script.js"></script>

Следи за порядком загрузки.

Если данные находятся в папке `data`, используй соответствующий путь.

---

# 22. Не ломать существующую функциональность

Перед изменением существующего кода:

1. Найди, где используется функция.
2. Проверь, не зависит ли от неё другая часть сайта.
3. Не удаляй старую функцию без необходимости.
4. Если новая система заменяет старую, сначала сделай новую систему рабочей.
5. Только после этого удаляй устаревший код.

Не переписывай весь проект ради небольшой функции.

---

# 23. Навигация

Боковая панель является основной навигацией сайта.

При выборе крупного раздела пользователь должен попадать на соответствующую страницу/секцию.

Для Церкви:

Клик по «Церковь» должен запускать:

showChurch()

а не просто:

showSection("church")

потому что `showChurch()` отвечает не только за открытие секции, но и за её первоначальное содержимое.

---

# 24. Дизайн

Текущий стиль сайта пользователю нравится.

Не переделывай внешний вид целиком без запроса пользователя.

При добавлении новых элементов:

- сохраняй существующую стилистику;
- используй уже существующие классы, если они подходят;
- не создавай пять разных вариантов одного и того же UI;
- не делай интерфейс чрезмерно перегруженным.

Пользователь предпочитает красивый, атмосферный интерфейс, но функциональность важнее декоративных элементов.

# 26. Не придумывать лор

Это очень важно.

Если информации о каком-либо объекте ещё нет:

не придумывай её самостоятельно.

Используй:

- "Описание пока не добавлено."
- пустую структуру;
- TODO;
- placeholder.

Особенно не придумывай:

- историю государств;
- религиозные догмы;
- способности;
- происхождение рас;
- отношения между персонажами;

Пользователь сам определяет канон Cartelia.

Агент отвечает за реализацию и структуру, а не за самостоятельное написание канона.

# 35. Главное правило

Не усложняй проект без необходимости.

Лучше:

простая структура данных
+
универсальный рендер
+
понятная навигация

чем:

много специальных функций
+
дублирование информации
+
огромный `script.js`
+
огромный `index.html`.

Главная цель — чтобы через несколько месяцев пользователь мог добавить новый элемент мира, изменив несколько строк в соответствующем `data/*.js`, а не переписывая сайт.
